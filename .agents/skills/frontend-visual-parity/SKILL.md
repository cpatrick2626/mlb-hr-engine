---
name: frontend-visual-parity
description: Use when matching an existing UI reference, layout, or visual system without redesigning unrelated surfaces.
---

- Confirm repo root, branch, and git status before edits.
- Match the provided reference or established design system closely.
- Change only the minimum UI needed to close the gap.
- Preserve adjacent screens and existing navigation.
- Validate responsive behavior if the screen is interactive.
- Report files changed, validation run, and final git status.
